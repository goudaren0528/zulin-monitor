# 配置 UI 与权重分配功能设计

## 背景

当前系统的配置管理存在以下问题：
1. Web UI 的"全局配置"只是一个原始 JSON 文本编辑器，不够直观
2. `keyword_mapping` 只支持简单映射（关键词 → 单商户），无法支持多商户权重分配

## 目标

1. 提供分区表单 UI，常用配置用表单编辑，复杂配置保留 JSON 编辑器
2. 支持同一关键词的多商户权重分配，按权重比例轮询分配订单

---

## 1. 配置文件结构变更

### 现有结构
```json
{
    "common": { "username": "...", "password": "...", "headless": true },
    "order_scanner": {
        "keyword_mapping": { "G7X2": "星享生活", "G7X3": "星享生活" }
    },
    "interface_monitor": { ... }
}
```

### 新结构
```json
{
    "common": { "username": "...", "password": "...", "headless": true },
    "order_scanner": {
        "keyword_mapping": {
            "G7X2": [
                { "merchant": "星享生活", "weight": 1 },
                { "merchant": "米奇租赁官方", "weight": 1 }
            ],
            "G7X3": [
                { "merchant": "星享生活", "weight": 2 }
            ]
        }
    },
    "interface_monitor": { ... }
}
```

### 兼容性处理
- 代码自动兼容旧格式（字符串）和新格式（数组）
- 旧格式视为单商家权重 1，无需手动迁移配置

## 2. 权重轮询算法

### 算法逻辑
1. 对于每个关键词，维护一个轮询索引（内存中）
2. 根据权重生成分配序列：
   - 例如 `[{merchant: "A", weight: 2}, {merchant: "B", weight: 1}]` → 序列 `[A, A, B]`
3. 每次分配时，按序列轮流选择，索引循环递增

### 实现位置
- `main.py` 的 `OrderScanner` 类新增 `_weight_router` 属性，存储每个关键词的轮询状态
- 在订单匹配逻辑处（约 933 行）调用轮询函数获取目标商家

### 日志格式
```
[2026-04-02 10:00:00] 订单 "G7X2 租赁" 匹配关键词 [G7X2] -> 分配给 [星享生活] (轮询: 1/3, 权重比 2:1)
[2026-04-02 10:01:00] 订单 "G7X2 租赁" 匹配关键词 [G7X2] -> 分配给 [星享生活] (轮询: 2/3)
[2026-04-02 10:02:00] 订单 "G7X2 租赁" 匹配关键词 [G7X2] -> 分配给 [米奇租赁官方] (轮询: 3/3)
```

| 区域 | 表单字段 | 说明 |

| common | username, password, headless | 基础登录配置 |

| order_scanner | keyword_mapping | 表格编辑（关键词 + 多商家权重） |
| order_scanner | webhook_configs, rpa_group_mapping | JSON 编辑器 |
| interface_monitor | url, scan_interval, webhook_url, headless | 监控参数 |
| interface_monitor | items | JSON 编辑器 |

## 4. API 端点变更

### 新增端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/config/common` | GET/POST | 读写 common 配置 |
| `/api/config/order_scanner` | GET/POST | 读写 order_scanner 配置（不含 keyword_mapping） |
| `/api/config/keyword_mapping` | GET/POST | 专门读写 keyword_mapping |
| `/api/config/interface_monitor` | GET/POST | 读写 interface_monitor 配置 |
| `/api/config/advanced` | GET/POST | 读写高级配置（webhook_configs, rpa_group_mapping, items） |

### 响应格式示例
```json
// GET /api/config/keyword_mapping
{
    "G7X2": [{"merchant": "星享生活", "weight": 1}],
    "G7X3": [{"merchant": "米奇租赁官方", "weight": 2}]
}

// POST /api/config/keyword_mapping
// 请求体同上，保存后返回 {"status": "success"}
```

### 保留原有端点
- `/api/config` (GET/POST) 保留，用于完整配置的读写（兼容性）

## 6. 兼容性与错误处理

### 兼容性保证
- 旧配置文件（字符串格式 keyword_mapping）自动兼容，无需手动迁移
- 原有 `/api/config` 端点保留，不影响现有功能

### 错误处理
- 表单提交前验证：权重必须为正整数、商家名不能为空
- JSON 编辑器提交前验证 JSON 格式正确性
- 配置保存失败时显示错误提示，不覆盖原配置
